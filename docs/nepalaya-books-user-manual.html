1. What this system is

Nepalaya Books is the operating system for Nepalaya Publication after books leave the printer. It tracks where every copy is, moves stock between Main Warehouse → Backroom → Bookstore Floor, and sells only from Bookstore Floor stock through the Point of Sale (POS).

It is not a full ERP or general warehouse product. It is built to feel like Square POS + a simple warehouse app.

Core rule

Every physical copy lives in exactly one place. Stock always moves. It never duplicates. If POS shows 0, the book cannot be sold — even if the warehouse is full.

Three locations

LocationPurposeTypical work
Main Warehouse Long-term storage of print runs Receive, label cartons, store, send to Backroom
Backroom Buffer next to the shop Receive transfers, open cartons, put on sale
Bookstore Floor Retail shelf stock (POS only) Sell, return, shelf adjustments

Cartons (boxes)

A carton holds copies of one title and has a barcode like NPBX-PW-000042.

Status (on screen)Meaning
FullSealed carton, not opened
OpenPartially used / remainder carton
EmptyNo copies left in the carton
In transitOn a transfer between locations

3. The big picture (stock flow)

Printer ↓ Receive (create Full + Open cartons, print labels) Main Warehouse ↓ Transfer → Send Backroom ↓ Transfer → Receive, then Put on sale Bookstore Floor ↓ POS sale Customer

Happy path (one print run)

Receive at Main Warehouse — choose book, total qty, copies per carton → create cartons → print labels → stick on boxes.
Send cartons Main Warehouse → Backroom (scan cartons, tap Send).
Receive the transfer at Backroom.
Put on sale — scan carton, move N copies to Bookstore Floor.
Sell on Store POS (only Bookstore Floor stock appears).

4. Getting started

Sign in

  1. Open the Nepalaya Books web app (desktop or tablet; Chrome / Safari recommended).
  2. Enter the email and password provided by Admin.
  3. If login fails: check Caps Lock, ask Admin to reset your password, or use “Forgot password” if enabled.
Camera scanning needs HTTPS (or localhost). On the phone/tablet, allow camera permission when asked.

Navigation

  • Desktop: left sidebar — Dashboard, Books, Warehouse tools, Store POS, Reports, Settings.
  • Phone/tablet: bottom tabs for the most common actions (Sell / Scan / Home, etc.).
  • Press ? anytime to reopen the in-app help guide.

First-time tip

Complete one small loop with a supervisor: Receive a tiny qty → Send → Receive → Put on sale → make a test sale (and void/return if needed). That teaches 90% of the product.

5. Cashier guide

Your job: serve customers quickly and keep Bookstore Floor stock accurate.

5.1 Open Store POS

Go to Store POS.
Search by title, author, or ISBN. Only books with Bookstore Floor stock are sellable.
Tap a book to add it to the cart. Adjust quantity with + / −.
Optional: add customer phone/name, apply discount if allowed.
Tap checkout → choose payment (cash / card / eSewa / Khalti as configured) → confirm.
On success, use Next sale to clear and serve the next customer. Print receipt if needed.

5.2 Returns

  1. In POS, open Process Return.
  2. Search by customer phone.
  3. Select the sale, choose quantities to return, enter a reason (required).
  4. Confirm — stock returns to Bookstore Floor; refund amount is recorded.

5.3 Close shift

Use Close shift when your shift ends. Confirm the day’s totals shown in the dialog before closing.

5.4 What Cashiers should not do

  • Do not invent stock — if POS says out of stock, ask Warehouse to Put on sale.
  • Do not receive print runs or create warehouse transfers.

5.5 Cashier troubleshooting

ProblemSolution
Book missing in POSCheck Bookstore Floor stock (Books detail). Ask Warehouse to put on sale from a carton.
“Max stock reached”You already have all available floor units in the cart.
Sale failed after paymentDo not tap Pay again with a new cart. Refresh, check if the sale appears. Contact Admin — retries are safe (idempotent).
Wrong priceAsk Admin/Warehouse to update the book MRP in Books → Manage.
Forgot passwordAsk Admin → Settings → Staff accounts → Reset password or Email reset.

6. Warehouse guide

Your job: keep cartons labeled, moves honest, and the shop floor stocked.

6.1 Receive a print run

Menu: Warehouse → Receive

Confirm location is Main Warehouse (default).
Search and select the book.
Enter total copies and copies per carton. Preview shows how many Full vs Open cartons will be created.
Optional: batch ref, shelf, notes.
Tap Receive & create cartons.
On success: Print labels (stick them on), or Send these cartons to open Transfers with boxes preselected, or Done.
Remainder copies (not a full carton) become an Open carton automatically — still label it.

6.2 Send a transfer (Main → Backroom)

Menu: Warehouse → Transfers

Tap New transfer. From = Main Warehouse, To = Backroom (defaults).
Scan cartons (camera or USB/type). Remove mistakes from the list.
Primary action: Send — creates the transfer and ships immediately.
Use Save draft only if you must pause mid-scan.
After Send, cartons are In transit. Someone at the destination must Receive them.

6.3 Receive a transfer

  1. Open Transfers → find status Sent.
  2. Confirm cartons physically arrived.
  3. Tap Receive. Cartons now sit at the destination location.

6.4 Put on sale (Backroom / warehouse → Bookstore Floor)

Menu: Scan (fastest) or Cartons / Book detail

Open camera or type/USB-scan the carton barcode.
Tap Put on sale, enter quantity (default = full remaining).
Confirm. Copies move to Bookstore Floor; carton becomes Open or Empty.
Scanner clears for the next carton — keep going.

6.5 Cartons list

Menu: Warehouse → Cartons. Default filter is All warehouses. Filter by status/location, multi-select to print labels or export.

6.6 Cycle count

Menu: Warehouse → Cycle count

  1. New count → choose location and method.
  2. Enter counted quantities.
  3. Complete — system adjusts inventory for differences (audit recorded).
Only complete a count when physical counting is finished. Cancelling discards entered counts.

6.7 Shelf locations

Define aisle/rack/bin codes, then use Scan → Set shelf (put-away) so cartons are findable.

6.8 Warehouse troubleshooting

ProblemSolution
Carton “already in transit”Open Transfers → Receive at destination. Do not create a second transfer for the same carton.
Stuck draft transfer (>24h)Dashboard warns you — open Transfers, Send or Cancel the draft.
Camera won’t scanUse HTTPS; allow camera; good light; hold steady. Or type / USB wedge scanner into the box code field.
Shop out of stock but warehouse fullPut on sale from Backroom/Main cartons — POS only sees Bookstore Floor.
Label won’t printAllow pop-ups for the site; retry Print labels from Receive success or Cartons.

7. Admin guide

Your job: keep people, prices, and permissions healthy — and unblock the team.

7.1 Staff accounts

Menu: Settings → Staff accounts

  • Add user — name, email, temporary password, role (Cashier / Warehouse / Admin).
  • Reset password — set a temp password; share securely (shown only once in the dialog).
  • Email — send a password reset email when email auth is configured.
  • Change role — promote/demote staff.
  • Activate / Deactivate — deactivated users cannot sign in.
Never reset or deactivate your own Admin account without another Admin available.

7.2 Books catalog

Books → Manage — create/edit titles, MRP, cost, ISBN, min stock alerts. Soft-delete carefully.

7.3 Discounts & locations

  • Settings → Discounts — store rules for POS.
  • Settings → Locations setup — Main Warehouse / Backroom / Bookstore Floor.
  • Warehouse → Locations — shelf bins.

7.4 Reports & audit

  • Reports — sales, inventory value, low stock, warehouse activity.
  • Staff accounts → Analytics / Sales / Audit — deeper history, voids, who did what.

7.5 Voiding a sale

From Admin sales tools: void with a written reason. Voided sales should not remain in revenue totals.

7.6 Admin troubleshooting

ProblemSolution
Staff locked outReset password or reactivate profile.
“You don’t have access”Wrong role — change role or open the correct menu.
Preview/login white screenEnsure Vercel has Supabase env vars; hard-refresh.
Numbers look wrong after a bad receiveUse cycle count or supervised stock adjustment; check audit log.

9. Daily / weekly checklists

Opening (Cashier)

  • □ Sign in
  • □ Confirm POS loads and a few titles show stock
  • □ If shelves look empty, ping Warehouse before the rush

During the day (Warehouse)

  • □ Clear any Sent transfers waiting to Receive
  • □ Put on sale enough copies for the floor
  • □ Receive any new print runs and label cartons the same day

Closing (Cashier)

  • □ Close shift with confirmed totals
  • □ Sign out on shared tablets

Weekly (Admin / Warehouse)

  • □ Review low-stock and reprint candidates in Reports
  • □ Spot-check cycle count on one shelf or one title
  • □ Deactivate former staff accounts

10. Troubleshooting & solutions

Login & access

SymptomFix
Incorrect email/passwordRetry carefully; Admin reset password
Account deactivatedAdmin must reactivate
Redirected from a pageRole lacks permission — toast explains

Scanning

SymptomFix
Camera permission deniedSite settings → Allow camera → Try again
Won’t decodeBetter light, fill the frame, clean lens; or type the code
“No box found”Confirm label matches system barcode; check Cartons list

Stock & sales

SymptomFix
Insufficient stock errorRefresh; verify location qty; don’t force negative stock
Double-tap created one sale onlyExpected — system uses request IDs to prevent doubles
Return rejectedReason required; sale may already be fully returned

If something goes wrong mid-flow

Stop and check status before repeating the action. Carton already Sent → Receive it. Sale maybe recorded → check Sales / Reports. Repeating a finished step often fails with a clear message — read it.
